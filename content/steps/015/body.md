## 問い

そらまめマーケットのネット通販では、来年の販促の予定を立てています。経営企画部のあなたは「売上が多いのは何月か、何曜日か」を調べるよう頼まれました。注文明細の注文日を日付として扱い、月ごと・曜日ごとに売上を集計します（会社もデータも架空のものです）。

## 文字の日付と日付型

このステップの `orders_raw` は、第10ステップで学んだ `col_types` を使い、注文日 `order_date` をわざと文字列として読み込んであります。ほかのシステムから届いたデータや、Excel から書き出したデータでは、日付がこのように文字のままになっていることがよくあります。

```r
glimpse(orders_raw)
```

`order_date` の型が `<chr>`（文字）になっていることを確かめてください。文字のままでは、「何月か」「何曜日か」を取り出せません。そこで日付型（Date）に変換します。

日付を扱うには lubridate パッケージが便利です。`ymd()` は「年（year）・月（month）・日（day）」の順に書かれた文字を日付型に変えます。

```r
ymd("2024-03-17")
orders <- mutate(orders_raw, order_date = ymd(order_date))
glimpse(orders)
```

型が `<date>` に変われば成功です。日本のデータは年・月・日の順に書くのがふつうですが、月・日・年の順なら `mdy()` のように、並び順に合わせた関数があります。

## 年・月・曜日を取り出す

日付型になれば、日付から必要な部分を取り出せます。

```r
d <- ymd("2024-03-17")
year(d)
month(d)
wday(d, label = TRUE)
```

`year()` は年、`month()` は月を数値で返します。`wday()` は曜日を返します。そのままだと日曜日を1とする数字ですが、`label = TRUE` を付けると曜日の名前になります。表示は「日・月・…」のこともあれば、環境によっては「Sun, Mon, …」のこともあります。曜日の名前は日曜から土曜の順に並ぶように作られているので、集計表も曜日の順に並びます。

これを `mutate()` で列にすれば、第6ステップと同じ方法で集計できます。

```r
orders |>
  mutate(sales = qty * unit_price,
         weekday = wday(order_date, label = TRUE)) |>
  group_by(weekday) |>
  summarise(sales = sum(sales))
```

## 月の初日にそろえる：floor_date()

月ごとの売上を求めるとき、`month()` だけでグループに分けると、2024年3月と2025年3月が同じ「3」にまとまってしまいます。年と月をまとめて扱いたいときは、`floor_date()` で日付を月の1日に切り下げます。floor は「床」、つまり切り下げるという意味です。

```r
floor_date(ymd("2024-03-17"), unit = "month")
```

`unit = "week"` なら週の初め、`unit = "year"` なら年の初めにそろえられます。結果は日付型のままなので、時間の順に並び、後の部で折れ線グラフにするときにもそのまま使えます。

## 季節の動きを読む

月次売上を並べると、増えたり減ったりする月があります。そのとき、変化が毎年同じ時期にくり返すかどうかを見ます。毎年くり返す動きを**季節性**と呼びます。季節性は、その年だけの出来事とは分けて考えます。

注意したいのは、売上全体が伸びているときです。全体が伸びていると、早い時期の月は、季節に関係なく小さく見えます。ある月が特に多い・少ないかは、すぐ前後の月や、前年の同じ月と比べて判断しましょう。実際に `monthly` を表示して、12月と8月がそれぞれ前後の月とどう違うかを確かめてください。

## 卒論・実務での使いどころ

日付を月や曜日にまとめて集計する作業は、販促の時期を決める実務でも、月次の統計を扱う卒論の時系列分析でも、最初に必ず行う準備です。
