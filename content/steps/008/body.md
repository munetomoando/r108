## 問い

上司に頼まれた集計のコードを実行したら、赤い英語のメッセージが出て止まってしまいました。このコードはなぜ動かないのでしょうか。このステップでは、エラーメッセージの読み方と、AI が書いたコードを自分で確かめる方法を練習します。

## エラーメッセージは「どこで・何が」を教えてくれる

R のエラーは英語で表示されますが、決まった形の短い文がほとんどです。よく出るものを覚えておけば、慌てずに済みます。

```r
stors |> head()
#> Error: object 'stors' not found
```

`object '…' not found` は「その名前の**オブジェクト**（R が覚えているデータや値）が見つからない」という意味です。原因の多くは、綴りの間違いか、代入する行をまだ実行していないことです。R は大文字と小文字も区別します。

```r
stores |> fliter(region == "関東")
#> Error in fliter(region == "関東") : could not find function "fliter"
```

`could not find function "…"` は「その名前の**関数**が見つからない」という意味です。原因は2つ考えられます。1つは関数名の綴り間違いです。もう1つは、その関数を含む**パッケージ**（関数をまとめた追加の道具箱）を読み込んでいないことです。たとえば `filter()` は dplyr というパッケージの関数なので、使う前に `library(dplyr)` を実行する必要があります。このアプリでは、各ステップの準備の段階で必要なパッケージをすでに読み込んでいます。そのためアプリの中では、まず綴りを疑いましょう。

ほかにも、列名を間違えると「Column `…` doesn't exist」や「object '…' not found」と出ます。`Error in` の後ろには、エラーが起きた関数の名前が書かれていることが多く、どの行で止まったかの手がかりになります。このアプリでは、よく出るエラーには日本語の説明も添えて表示します。英語の原文と日本語の説明を見比べると、次第に原文だけで読めるようになります。

## 関数の使い方を調べる ?関数

関数の引数（関数に渡す材料）を忘れたときは、`?` の後に関数名を書いて実行します。

```r
?slice_max
```

その関数の**ヘルプ**（説明書）が表示されます。英語ですが、「Usage」に書き方、「Arguments」に引数の意味、末尾の「Examples」に実行例があります。まず Examples を眺めると、使い方をつかみやすいでしょう。

## 1行ずつ実行して確かめる

パイプで長くつないだコードは、途中で何が起きているかが見えません。そこで、パイプの途中で切って実行し、1段ずつ結果を確かめます。

```r
stores |>
  filter(sales >= 100000)
```

ここで表を見て、意図した店舗が残っているか、何行あるかを確かめます。問題がなければ次の1行を足して実行します。これを繰り返すと、どの段で結果がおかしくなったかを突き止められます。エラーが出たときも同じです。最後の行から1段ずつ消して実行し、エラーが消えたところの次の行が原因だと分かります。

## AI のコードを読むときの注意

生成AIに頼むと、それらしいコードがすぐに返ってきます。しかし、エラーが出ないことと、正しいことは別です。特に多いのは、絞り込みと集計の順番の誤りです。「大型店に絞ってから地域で集計する」べきところを、「地域で集計してから絞る」コードになっていても、エラーは出ずに表が表示されることがあります。そのまま会議資料に載せれば、誤った数字で判断を誤らせてしまいます。

AI のコードを使うときは、次の3点を確かめましょう。

1. 各行が何をしているかを、日本語で言えるか
2. 途中の結果を1段ずつ表示して、行数や列が想定どおりか
3. 結果が、頼まれた問いに答える形になっているか

## 卒論・実務での使いどころ

AI が書いたコードでも、1行ずつ実行して意味を確かめてから使えば、報告書や卒論に載せる数字に自分で責任を持てるようになります。
