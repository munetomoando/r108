## 問い

第93ステップの予測モデル（曜日・月・気温）に、祝日と雨を加えたら良くなるでしょうか。上司からは「テスト期間の成績が良いほうを選べばいい」と言われました。しかし、テスト期間の成績を見ながらモデルを何度も選び直すと、テスト期間に合わせたモデルを選ぶことになり、テスト期間が「まだ見ていないデータ」ではなくなります。では、モデルの比較はどうすれば公平になるでしょうか。

## 交差検証

答えは、**訓練期間の中でもう一度「推定用」と「検証用」に分けて比べる**ことです。1回だけ分けると、分け方の偶然で結果が変わります（第92ステップでは、13日のテストデータで比べました）。そこで、訓練データを5つのグループ（fold）に分け、「1つを検証用、残り4つを推定用」にして5回評価し、平均します。これを**5分割交差検証**（cross-validation）といいます。どの日も1回ずつ検証用になります。

```r
set.seed(108)
folds <- vfold_cv(train, v = 5)
```

`vfold_cv()` は無作為に分けるので、`set.seed()` で乱数を固定します。訓練期間731日が、検証用146〜147日ずつに分かれます。

## 2つのモデルを比べる

モデルA（`wf_a`）は第93ステップと同じ曜日・月・気温、モデルBは祝日 `holiday` と雨 `rain` を加えたものです。`fit_resamples()` は、5回の「推定して評価する」をまとめて行い、`collect_metrics()` で結果の平均を取り出します。

```r
res_a <- fit_resamples(wf_a, resamples = folds)
res_b <- fit_resamples(wf_b, resamples = folds)
collect_metrics(res_b)
```

指標は、何も指定しなければ RMSE（rmse）と決定係数（rsq）です。`mean` が5回の平均、`std_err` がその標準誤差です。RMSE はモデルAが約0.104、モデルBが約0.083で、標準誤差（約0.005と0.002）と比べてもはっきりした差です。祝日と雨は予測に役立つので、モデルBを選びます。

## 最後にテスト期間で確かめる

モデルを選んだら、訓練期間全体で推定し直し、それまで一度も使っていないテスト期間（2025年）で確かめます。`metrics()` は、実際の値（truth）と予測値（estimate）から RMSE・決定係数・MAE をまとめて計算します。

```r
fit_b <- fit(wf_b, data = train)
augment(fit_b, new_data = test) |>
  metrics(truth = log_sales, estimate = .pred)
```

テスト期間の RMSE は約0.085、MAE は約0.068で、交差検証の値（約0.083）とほぼ同じでした。モデルAの約0.107より小さくなっています。報告では「交差検証でモデルを選び、選んだモデルをテスト期間で確かめた」という順番を守ります。

## 時系列データでの注意

ここでは日付と関係なく無作為に分けたので、2024年の日で推定して2023年の日を評価する組み合わせも入っています。このモデルは同じ日の曜日・月・気温・祝日・雨だけを使うので、その影響は小さく、テスト期間でもほぼ同じ精度でした。しかし前日や前年の売上（第73ステップのラグ）を説明変数に使うと、無作為な交差検証は精度を良く見せすぎます。そのときは第9部のように「過去で推定し、その後の期間で評価する」分け方をくり返します（rsample の `rolling_origin()` など）。

また、モデルBの祝日の係数は約0.17、雨は約 −0.10 ですが、祝日や雨は会社が動かせるものではありません。係数は予測のための関係で、施策の効果ではないことは第91ステップと同じです。

## 卒論・実務での使いどころ

複数のモデルを比べるときは、交差検証の平均と標準誤差で選び、選んだ1つだけを最後にテストデータで評価して、その値を精度として報告します。
