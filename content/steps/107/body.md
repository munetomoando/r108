## 問い

第90ステップでは、そらまめマーケット（架空の会社）の広告キャンペーンの効果を差の差分析で推定し、費用対効果を計算しました。分析はそこで終わりではありません。経営会議の出席者が数分で読み、「続けるか、やめるか」を決められる形にして初めて、分析は仕事の役に立ちます。このステップでは、同じ結果をどう並べ、どの図で見せ、1枚にどうまとめるかを考えます。

## 結論を先に書く

学校のレポートは「目的→方法→結果→考察→結論」の順に書くことが多く、結論は最後に来ます。仕事の報告では順序が逆で、**結論を最初に**書きます。読み手は忙しく、最初の数行しか読まないかもしれないからです。結論の後に、それを支える根拠を、重要なものから順に置きます。

経営者が知りたいのは、たいてい次の3つです。

1. 何が起きたか（効いたか、どれだけか）
2. それはお金にするといくらか（もうかったか）
3. だから何をすべきか（続けるか、やめるか、何を確かめるか）

数字は、読み手が判断に使える単位に直します。「係数0.0715」ではなく「注文が約7%増えた」、「p = 0.022」ではなく「増えた粗利は約40万円で、広告費35万円をわずかに上回る」と書きます。不確かさも隠さずに書きます。第90ステップの結果では、95%信頼区間の下限では約29万円の赤字、上限では約37万円の黒字でした。「黒字です」とだけ書くと、読み手は確かな黒字だと受け取ってしまいます。分析の手順やデータの大きさは、聞かれたときに答えられるように付録に回します。

## 図は目的から選ぶ

図は「この図で何を見せたいか」を1文で決めてから選びます。

| 見せたいこと | 向いている図 |
| --- | --- |
| 時間とともにどう変わったか | 折れ線グラフ（横軸が時間） |
| 項目の大きさの比較 | 棒グラフ（大きい順に並べる） |
| 2つの量の関係 | 散布図 |
| 推定値とその不確かさ | 点と区間の図（`geom_pointrange()`） |

第90ステップの図は、実施県と非実施県のそれぞれで、キャンペーン前の月平均を100とした指数の折れ線でした。水準の違う群を指数にそろえると、「前は同じように動き、開始後に離れた」ことが一目で分かります。開始時点の縦線や、図のタイトルに結論を書くこと（例「実施県の注文は6月以降に約7%上振れ」）も、読み手の目を導きます。1枚の資料に載せる図は、1つか2つに絞ります。

## 1枚の要約を Markdown で書く

経営会議の資料は、1枚の要約から始めます。Markdown で書いておけば、第100ステップの Quarto でそのまま Word や HTML にできます。c では、Markdown の1行を文字列1つにして並べ、`writeLines()` で表示します。`writeLines()` は、文字のベクトルを1要素ずつ改行して表示する関数です。

```r
memo <- c(
  "# 広告キャンペーンの効果と費用",
  "",
  "## 結論",
  "注文は約7%増えたが、赤字の可能性も残る。",
  "",
  "## 根拠",
  paste0("- 増えた粗利は約", round(roi$extra_profit[2] / 10000), "万円。")
)
writeLines(memo)
```

`paste0()` は、文字と数字を区切りなしでつなげる関数です。数字を手で写さずに `roi` から作ると、データが更新されても書き写しの誤りが起きません。要約は「見出し」「結論」「根拠」「次の一手」の4つで作ります。見出しには、何についての要約かが分かる言葉を入れます。結論は3行以内にします。根拠には推定値と信頼区間、費用対効果の幅、前提（平行トレンド）を箇条書きで置きます。次の一手には、実施県を無作為に選んで測り直す、期間を延ばして推定の幅を狭める、といった具体的な行動を書きます。

## 卒論・実務での使いどころ

報告を書く前に「読み手は誰で、何を決めるために読むのか」を1文で書き出し、結論・根拠・次の一手の順に1枚にまとめてから、図と付録を足していきます。
