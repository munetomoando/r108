## 問い

店長会議で「来年の日ごとの売上の見込みがあれば、仕入れやパートの勤務表が組みやすい」という声が出ました。上司からは、藤沢店で試しに予測モデルを作るよう頼まれています。このステップでは、機械学習でよく使う **tidymodels** の書き方で、2023〜2024年のデータから2025年の売上を予測します。

**はじめに**：tidymodels は複数のパッケージの集まりです。ステップを初めて開いたときは、パッケージの読み込みに十数秒〜数十秒かかることがあります。

## データと期間の分け方

`fuji` は藤沢店（S14）の2023〜2025年の1,096日分で、売上の対数 `log_sales` を加えてあります。来年を予測するモデルなので、第78ステップと同じく、**2024年までを訓練期間 `train`、2025年をテスト期間 `test`** に分けます（第92ステップの無作為な分け方は使いません）。

## tidymodels の4つの部品

tidymodels では、予測の作業を次の部品に分けて書きます。

| 部品 | 役割 | 関数 |
| --- | --- | --- |
| レシピ | 何を何で予測するか、前処理の手順 | `recipe()`、`step_date()` など |
| モデル | どんな式で予測するか | `linear_reg()`（線形回帰） |
| ワークフロー | レシピとモデルをまとめたもの | `workflow()`、`add_recipe()`、`add_model()` |
| 推定と予測 | データで推定し、新しいデータを予測 | `fit()`、`predict()`、`augment()` |

## レシピ：日付から曜日と月を作る

```r
rec <- recipe(log_sales ~ date + temp, data = train) |>
  step_date(date, features = c("dow", "month"), keep_original_cols = FALSE)
```

`recipe()` の式は `lm()` と同じで、`~` の左が予測したい変数（目的変数）、右が予測に使う変数です。`step_date()` は日付から曜日（dow）と月（month）の列を作る手順で、`keep_original_cols = FALSE` で元の date 列を消します。レシピは「設計図」なので、この時点ではまだ計算していません。

## ワークフローで推定する

```r
wf <- workflow() |>
  add_recipe(rec) |>
  add_model(linear_reg())
wf_fit <- fit(wf, data = train)
```

`fit()` は、レシピの手順を訓練データに当てはめてから、線形回帰を推定します。`wf_fit` を表示すると、中身の `lm()` の係数が見えます。temp の係数は約0.0103で、気温が1℃高いと売上が約1%多いという関係です。

## テスト期間を予測する

```r
predict(wf_fit, new_data = test)          # 予測値 .pred だけの表
test_pred <- augment(wf_fit, new_data = test)   # test に .pred と .resid を加えた表
```

新しいデータにも、`fit()` のときと同じレシピの手順（曜日と月を作る）が自動で当てはめられます。予測と元のデータを並べて扱いたいときは `augment()` が便利です。

2025年の RMSE は約0.107、MAE は約0.085でした。対数なので、日々の売上をおよそ10%前後の誤差で予測できたことになります。比べる相手として、訓練期間の平均をそのまま予測値にすると RMSE は約0.181です。曜日・月・気温を使うことで、誤差がかなり小さくなりました。予測値を円に戻すときは `exp(.pred)` とします。

ただし、このモデルには祝日や雨が入っていません。変数を増やすと良くなるのか、その比べ方を第94ステップで学びます。なお、気温の係数は予測に役立つ関係で、「店内を暖めれば売上が増える」という因果を表すものではありません（第91ステップ）。

## 卒論・実務での使いどころ

レシピとモデルを分けて書いておくと、変数を足したりモデルを替えたりしても、推定・予測・評価のコードをそのまま使い回せます。
