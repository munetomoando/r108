## 問い

第II段階（ステップ28〜54）の関門です。統計と回帰（第4・5部）、論文の書き方と再現性（第6部）で学んだことを全部使い、自分で立てた問いに、データと回帰分析で答える**4,000字程度のミニ卒論**を書きます。卒論の本番を小さくした練習で、ここで作った原稿と分析の形は、そのまま卒論の出発点になります。

## ミニ卒論の形

見出しは次の5つを、この順に置きます。字数は本文の目安です。

| 見出し | 目安 | 書くこと |
| --- | --- | --- |
| 問い | 600〜800字 | 1文の疑問文にした問い、なぜ大事か、先行研究（3件以上を引用） |
| データ | 600〜800字 | 出所・単位・期間・観測数、変数の定義、記述統計や図 |
| 方法 | 600〜800字 | 推定する式、入れる変数とその理由、標準誤差の種類 |
| 結果 | 1,000〜1,400字 | 回帰表、係数を単位つきの言葉で読む、モデルによる違い |
| 結論 | 600〜800字 | 問いへの答え（数字で）、限界2つ以上、今後の課題 |

データは `pref_panel`（47都道府県×2019〜2025年）か、自分で選んだ公開データ（e-Stat の統計表、wooldridge パッケージのデータなど）を使います。`pref_panel` なら、たとえば次のような問いが立てられます。

- 最低賃金を大きく引き上げた県ほど、平均時給も大きく伸びたか
- カイツ指標（最低賃金÷平均時給）の地域差は、2019年から2025年にかけて縮んだか
- 人口の多い県ほど平均時給は高いか。その差は最低賃金の差で説明できるか

問いの類型（記述・因果・予測、ステップ46）を意識します。都道府県の集計データの回帰では、因果効果までは言えないことが多いので、「関係がどれだけあるか」を正確に述べ、因果と言えない理由を限界に書きます。

## 手順

1. ステップ53で作ったプロジェクト `minwage` を開きます（RStudio は「File」→「Open Project...」、Positron は「File」→「Open Folder...」）。
2. 雛形 [mini_thesis.qmd](local/mini_thesis.qmd) をダウンロードし、プロジェクトのフォルダ（`.Rproj` と同じ場所）に移します。同じ場所に、ステップ52の [references.bib](local/references.bib) も置きます。`data/pref_panel.csv` はステップ53で置いたものを使います。
3. このプロジェクトは renv を使っているので、論文に要るパッケージをプロジェクトに入れます。コンソールで `install.packages(c("rmarkdown", "knitr", "modelsummary", "fixest", "ragg"))` を実行し、終わったら `renv::snapshot()` で `renv.lock` を書き直します。
4. 雛形を開き、まず何も変えずに Render（Positron は Preview）を押します。同じフォルダに `mini_thesis.docx` ができれば準備完了です。Windows はエクスプローラー、macOS は Finder でフォルダを開き、ダブルクリックで中を確かめます。
5. YAML ヘッダの `title` と `author` を書き換え、5つの節を書きます。雛形の `<!--` と `-->` で囲んだメモに、各節で書くことがあります（このメモは Word に出ず、字数にも数えません）。
6. 図を2つ以上（ラベル `fig-…` とキャプション `fig-cap`）、回帰表を1つ以上（ラベル `tbl-…`）作り、本文で `@fig-…`・`@tbl-…` と参照します。文献は `references.bib` に足し、本文で3件以上を `@キー` で引用します。
7. ときどき Render して、Word で見た目を確かめます。書き終えたら、下の点検表で見直し、確認スクリプトを実行します。

## 回帰表を Word に出す

modelsummary の表をそのまま Word に出すと、係数名などに日本語があるとき、表の列がずれて崩れることがあります。雛形では、表をいったんデータフレームにしてから `knitr::kable()`（ステップ51）で出しています。

```r
tab <- modelsummary(models, vcov = "HC1",
  coef_map = c("log(min_wage)" = "最低賃金（対数）"),
  gof_map = c("nobs", "r.squared"), fmt = 3, output = "data.frame")
tab |>
  mutate(term = if_else(statistic == "std.error", "", term)) |>
  select(-part, -statistic) |>
  knitr::kable(col.names = c("", names(models)), align = "lrr")
```

`output = "data.frame"` の表には、係数の行と標準誤差の行が交互に並び、`statistic` の列でどちらかが分かります。標準誤差の行の変数名を空にして、`part` と `statistic` の列を落とすと、論文の回帰表の形になります。雛形のまま出すと、(1) の係数は約0.94、年ダミーを加えた (2) は約1.36です。県の固定効果を入れるなら、fixest の `feols(log(avg_wage) ~ log(min_wage) | pref + year, data = panel)` を `models` に加え、`vcov` を `list("HC1", "HC1", ~pref)` のようにモデルごとに指定します。表の下には「括弧内は何の標準誤差か」を注として書きます。

## 字数の数え方

確認スクリプトは、YAML ヘッダ・コードチャンク・`<!-- -->` のメモ・見出しの行を除いた本文から、空白と改行を除いた文字数を数えます。句読点・数字・英字も1文字ずつ数えます。Word の「文字カウント」の「文字数（スペースを含めない）」に近い数ですが、表や図のキャプション、文献リストは含まないので、Word の数より少なくなります。

目安は4,000字で、**下限はおおむね3,000字**です。下限を超えていても、5つの節のどれかが数行しかなければ、点検表で引っかかるはずです。字数を増やすために同じことをくり返すのではなく、データの定義、係数の読み方、限界を具体的に書き足します。

## 合格の基準

次の2つがそろえば合格です。

**(1) 確認スクリプトの全項目に ✓ が付く。** 確かめるのは、`mini_thesis.qmd` があること、題名と自分の名前、5つの見出しの順番、本文3,000字以上、回帰表1つ以上、図2つ以上、3件以上の文献の引用、図表の相互参照、Word へのレンダリング、Word の中で図表と引用が解決していることです。

**(2) 下の点検表のすべてに「はい」と答えられる。** 確認スクリプトは形しか見ません。内容は自分で確かめます。

## 自分で見直す点検表

**問い**
- □ 問いを1文の疑問文で書き、データで答えられる形になっている
- □ 先行研究が何を明らかにしたかを、自分の言葉で1〜2文ずつ書いている

**データ**
- □ 調査名・作成者・年、観測の単位、期間、観測数を書いている
- □ 主な変数の定義と単位を書いている（例：平均時給＝所定内給与額÷所定内実労働時間数、円/時）
- □ 図のキャプションと軸に、何をいつ測った値か、単位、出所がある

**方法**
- □ 推定する式を書き、なぜその変数を入れるのかを説明している
- □ 標準誤差の種類（HC1、クラスター頑健など）を書いている

**結果**
- □ 主な係数を「〜が1%高いと〜が約0.4%高い」のように、単位をつけた言葉で読んでいる
- □ 係数が0と区別できるか（標準誤差・信頼区間）と、経済的な大きさの両方を述べている
- □ 本文の数字と表の数字が一致している

**結論**
- □ 問いへの答えを、数字を入れて書いている
- □ 因果効果とは言えない理由など、限界を2つ以上書いている
- □ 「証明された」「必ず」など、データが支えない強い言い方をしていない

**再現性**
- □ R を再起動してから Render しても、同じ Word ができる
- □ データを手で直しておらず、加工はすべてコードに書いてある
- □ 乱数を使うなら `set.seed()` があり、`renv.lock` が最新（`renv::status()` で確かめる）

## 卒論・実務での使いどころ

このミニ卒論の5つの見出し、回帰表と図、点検表は、そのまま卒論の骨組みとして使えます。データや期間を広げ、方法を第III段階の因果推論の手法に置き換えていけば、卒論の本番になります。
