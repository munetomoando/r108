## 問い

A/Bテストには、計算が正しくても誤った結論に至る落とし穴があります。上司からは「次のテストでは、毎日結果を見て、差が出たらすぐ止めればいいんじゃないか」と言われました。本当にそれでよいのでしょうか。途中で結果を見ること、割当比率のずれ、後付けのセグメント分析の3つを確かめます。

## 落とし穴1：毎日結果を見て、有意になったら止める

テストの途中で結果を見て、有意になったところで止めることを**のぞき見**（peeking）といいます。本当は差がないとき、これで何が起きるかをシミュレーションします。

`rbinom(14, 500, 0.04)` は、「500人が4%の確率で買う日」を14日分作り、毎日の購入者数を返す関数です（二項分布の乱数）。`cumsum()` で累計にすれば、d 日目までの購入者数になります。A と B を**どちらも4%**にして、差がない状態を作ります。

検定には `prop.test()` を使えますが、14日 × 1,000回で1万回以上呼ぶとブラウザでは時間がかかります。そこで同じ判定を式で行います。2群の購入率の差を、差がないときの標準誤差で割った値を $z$ とします。

$$z = \frac{\hat p_B - \hat p_A}{\sqrt{\bar p(1-\bar p)\,(1/n + 1/n)}}$$

$\bar p$ は2群を合わせた購入率です。$|z| > 1.96$ のとき5%水準で「有意」で、`prop.test(…, correct = FALSE)` のp値が0.05を下回るのと同じ判定です（$z^2$ がそのカイ二乗値に一致します）。

```r
set.seed(108)
hits <- replicate(1000, {
  xa <- cumsum(rbinom(14, 500, 0.04))
  xb <- cumsum(rbinom(14, 500, 0.04))
  n <- 500 * (1:14)
  pool <- (xa + xb) / (2 * n)
  z <- (xb / n - xa / n) / sqrt(pool * (1 - pool) * 2 / n)
  any(abs(z) > 1.96)
})
mean(hits)
```

`z` は14日分のベクトルで、`any(abs(z) > 1.96)` は一度でも「有意」になったかを表します。

結果は0.208で、差がないのに約21%の確率で「効果あり」と言ってしまいます。同じ乱数で**最終日だけ**検定すると（最後の行を `abs(z[14]) > 1.96` にする）、0.044で約5%に収まります。毎日検定するのは14回検定するのと同じで、一度でも0.05を下回る機会が増えます。第35ステップの多重比較と同じ問題です。

対策は、第86ステップのように**人数（期間）を先に決め、その人数に達するまで判断しない**ことです。途中で見ること自体は、システムの不具合を見つけるためなら構いません。

## 落とし穴2：割当比率がずれている（SRM）

`ab_srm` は、同じテストの記録に不具合があった版です（教材用の合成データ）。50:50で割り当てる設定なのに、A 10,200人・B 9,800人になっています。無作為に割り当てても人数は多少ずれますが、このずれは偶然の範囲でしょうか。第34ステップの `chisq.test()` に、表と本来の比率 `p` を渡すと確かめられます（**適合度検定**）。

```r
srm_tab <- table(ab_srm$group)
res_srm <- chisq.test(srm_tab, p = c(0.5, 0.5))
res_srm$p.value
```

p値は約0.0047で、偶然とは考えにくいずれです。第87ステップの `ab` で同じ検定をするとp値は1（ちょうど1万人ずつ）です。このように、割当比率が設定とずれていることを **SRM**（sample ratio mismatch）といいます。

SRM は、どこかで一部の訪問者が記録から落ちているしるしです。端末別に数えると、A の PC は4,080人なのに B の PC は3,680人で、B の PC 利用者が欠けています。実はこのデータでは、B の購入しなかった PC 利用者の一部が記録から落ちています。そのため ab_srm で第87ステップと同じ分析をすると、B の購入率は5.41%となり、本来の5.2%より高く見えます（小課題 d）。買わなかった人だけが落ちれば、効果は大きく見えます。**SRM が見つかったら、結果を報告する前に原因を調べます。**p値がいくら小さくても、比べている2群が無作為な2群ではなくなっているからです。

## 落とし穴3：後付けのセグメント分析

結果を端末別・年代別・地域別などに分けて調べることを**セグメント分析**といいます。第87ステップのテストを端末別に検定すると、スマホは A 3.5%→B 5.1%（p値 約0.00002）、PC は A 4.75%→B 5.35%（p値 約0.24）でした。

ここで「PC では効果がない」と結論するのは誤りです。PC は1群4,000人なので、第86ステップの方法で計算すると、検出力80%で見つけられる差は約1.4ポイントで、0.6ポイントの差を見つける検出力は約23%しかありません。有意にならないのは当然とも言えます。

また、結果を見てから分け方を選ぶと、分けた数だけ検定をくり返すことになります。10通りに分ければ、効果がなくても $1 - 0.95^{10} \approx 0.40$、つまり約40%の確率でどこかが有意になります。後から見つけたセグメントの違いは「次のテストで確かめる仮説」として扱い、分けて調べるなら、テストを始める前にどの分け方で比べるかを決めておきます。

## 卒論・実務での使いどころ

実験の結果を報告する前に、割当比率の検定（SRM の確認）、検定の回数と時期が事前の計画どおりだったか、セグメント分析が事前に決めたものか後付けかを確かめ、報告に書き添えます。
