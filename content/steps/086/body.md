## 問い

ネット通販の担当者が、購入画面を新しくしました。上司からは「新しい画面で本当に購入率が上がるのか、A/Bテストで確かめてほしい。何人に見せればいいか、始める前に教えてくれ」と言われています。テストは、始めてから考えるのでは遅すぎます。このステップでは、必要な人数の計算と、訪問者の分け方を学びます。

## A/Bテストとは

**A/Bテスト**は、ウェブサイトの訪問者を無作為に2つの群に分け、片方には今の画面（A）、もう片方には新しい画面（B）を見せて、購入率などを比べる方法です。第56ステップのランダム化比較試験（RCT）を、ネットの画面で行うものだと考えてください。ネット通販では、訪問者ごとに見せる画面を簡単に切り替えられるので、企業はこの方法をよく使います。

小課題 a〜d は、テストを始める前の**設計**の話です。まだデータはありません。第87ステップで、実際に行ったテストの結果（`ab_test`）を分析します。

## 何人に見せればよいか（power.prop.test）

第35ステップでは、平均の差を見つけるのに必要な人数を `power.t.test()` で計算しました。購入率のような**割合**の差では、`power.prop.test()` を使います。

```r
pw <- power.prop.test(p1 = 0.04, p2 = 0.05, power = 0.8)
ceiling(pw$n)
```

`p1` は今の購入率（過去のデータから約4%）、`p2` は「これだけ上がるなら見つけたい」購入率です。`p2` には差の0.01ではなく、購入率そのものの0.05を書きます。`power = 0.8` は、本当に5%に上がっているとき、80%の確率で「有意」と判定できること（**検出力**80%）を求める指定です。有意水準 `sig.level` は既定の0.05のままです。

結果の `n` は**1群あたり**の人数で、約6,744.9人です。人数は小数で出るので、`ceiling()`（小数を切り上げる関数）で切り上げて、1群6,745人、2群で13,490人が必要だと分かります。

見つけたい差を変えると、必要な人数は大きく変わります。

| 見つけたい購入率 | 差 | 1群あたりの人数 |
| --- | --- | --- |
| 6% | 2ポイント | 1,863人 |
| 5% | 1ポイント | 6,745人 |
| 4.8% | 0.8ポイント | 10,317人 |

差が半分になると、人数はおよそ4倍になります。小さな差を見つけるには、多くの訪問者が必要です。

## 人数が決まっているときは（最小検出効果）

実際には「何人必要か」より、「この期間に来る人数で、どれだけの差を見つけられるか」を問われることが多いです。`power.prop.test()` は、5つの値（`n`・`p1`・`p2`・`sig.level`・`power`）のうち書かなかった1つを計算します。`n` を書いて `p2` を書かなければ、見つけられる購入率が分かります。

```r
mde <- power.prop.test(n = 10000, p1 = 0.04, power = 0.8)
mde$p2 - 0.04
```

1群1万人なら、検出力80%で見つけられる最小の差は約0.81ポイント（4%→約4.81%）です。この値を**最小検出効果**（minimum detectable effect、MDE）といいます。本当の差がこれより小さいと、テストをしても「有意」にならないことが多くなります。上司が求めた1ポイントの差なら、1群1万人での検出力は約0.93です。

報告では「1群1万人で、購入率の約0.8ポイント以上の改善なら80%の確率で見つけられます。それより小さい改善は見逃すおそれがあります」のように、**何が分かり、何が分からないか**を先に伝えます。

## 無作為に割り当てる（sample）

訪問者を A と B に分けるときは、必ず**無作為**に分けます。第30ステップの `sample()` に、A を1万個・B を1万個並べたベクトルを渡すと、順番を無作為に並べ替えて、ちょうど1万人ずつに割り当てられます。

```r
set.seed(108)
visitors <- tibble(visitor_id = 1:20000,
                   device = sample(c("スマホ", "PC"), 20000, replace = TRUE, prob = c(0.6, 0.4)),
                   group = sample(rep(c("A", "B"), each = 10000)))
count(visitors, device, group)
```

`device` は、スマホ6割・PC4割の架空の訪問者を作るための列です（`prob` は選ばれる確率）。数えてみると、スマホは A 6,046人・B 5,983人、PC は A 3,954人・B 4,017人で、両群の構成はほぼ同じです。割当のときに端末を見ていないのに、無作為にしただけでそろいます。年齢や買う気の強さのような、データにない特徴も同じようにそろいます。だから、A と B の購入率の差を「画面の違い」によるものと読めます。

端末で分ける、週で分ける、希望者に新しい画面を見せる、といった分け方では、画面以外の違いが混ざってしまいます（小課題 d）。

## 卒論・実務での使いどころ

実験や施策のテストを計画するときは、始める前に「見つけたい差」「必要な人数（または人数から決まる最小検出効果）」「無作為な割当の方法」を決めて書き残しておきます。
