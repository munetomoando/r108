## 問い

上司から「藤沢店の土曜日の売上を、気温から予測できないか」と頼まれました。気温と売上の関係を直線でなく曲線で表せば、当てはまりはもっと良くなりそうです。では、曲線を複雑にするほど良い予測になるのでしょうか。

## データ

`sat` は、藤沢店（S14、神奈川県）の2025年の土曜日52日分です。`store_sales_daily` は、そらまめマーケットの30店舗の日次売上（教材用の合成データ）で、売上 `sales`（円）のほか、気温 `temp`、雨 `rain`、祝日 `holiday` があります。曜日による違いを除くため、土曜日だけを使います。売上は対数 `log_sales` にしておきます。対数の差は、おおよその変化率と読めます（第37ステップ）。

## 訓練データとテストデータ

モデルを推定したデータで当てはまりを測ると、実力より良く見えます。第78ステップでは、時系列の終わりをテスト期間として取っておきました。機械学習でも同じ考え方で、データを**訓練データ**（モデルの推定に使う）と**テストデータ**（答え合わせにだけ使う）に分けます。

`rsample` パッケージの `initial_split()` は、行を無作為に選んで2つに分ける「分け方」を作ります。中身は `training()` と `testing()` で取り出します。無作為に選ぶので、`set.seed()` で乱数を固定します。

```r
set.seed(108)
sat_split <- initial_split(sat, prop = 0.75)
train <- training(sat_split)   # 39日
test <- testing(sat_split)     # 13日
```

## 曲線を複雑にする

`poly(temp, 3)` は、temp、temp²、temp³ を説明変数に入れるのと同じ働きをします（第42ステップの `I(temp^2)` の続き）。次数を上げるほど、曲がりくねった曲線になります。

```r
m10 <- lm(log_sales ~ poly(temp, 10), data = train)
sqrt(mean((train$log_sales - predict(m10, train))^2))   # 訓練データでの RMSE
sqrt(mean((test$log_sales - predict(m10, test))^2))     # テストデータでの RMSE
```

`predict(m10, test)` は、訓練データで推定したモデルで、テストデータの売上を予測します。

## 過学習

次数1・3・10を比べると、訓練データでの RMSE は約0.105、0.103、0.092と、次数を上げるほど小さくなります。ところがテストデータでは約0.128、0.125、0.752で、次数10だけが大きく外れます。対数の RMSE 0.1 は、およそ10%の誤差です。

図を描くと理由が分かります。次数10の曲線は、点の少ない寒い日のあたりで大きく曲がっています。訓練データの偶然の揺れまで追いかけてしまい、新しいデータで外れたのです。これを**過学習**（overfitting）といいます。複雑なモデルほど訓練データにはよく合いますが、まだ見ていないデータで当たるとは限りません。だから、モデルの良さはテストデータで測ります。

## 時系列のデータを無作為に分けてよいか

ここでは日付と関係なく無作為に分けました。このモデルは同じ日の気温だけで売上を説明するので、日付の順番はあまり問題になりません。しかし「来年の売上を予測する」なら、第9部と同じく、過去の期間で推定し、それより後の期間で確かめるのが正しい分け方です。無作為に分けると、未来の日のデータで推定して過去の日を予測することになり、実力より良く見えることがあります。第93ステップからは、2023〜2024年を訓練期間、2025年をテスト期間に分けます。

## 卒論・実務での使いどころ

予測モデルの精度を報告するときは、推定に使ったデータでの当てはまりではなく、推定に使わなかったデータ（テストデータやテスト期間）での誤差を示します。
