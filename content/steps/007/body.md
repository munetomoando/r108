## 問い

売上が多い上位5店では、客単価はどれくらいでしょうか。このステップでは、「列を作る」「行を絞る」「列を選ぶ」といった処理を、パイプでひと続きにつないで答えを出します。

## パイプ |> は「そして次に」

これまでのステップでも `|>` という記号を使ってきました。これを**パイプ**と呼びます。パイプは、左側の結果を右側の関数の最初の引数（関数に渡す材料）として渡す記号です。次の2つの書き方は同じ意味です。

```r
head(stores)
stores |> head()
```

パイプが役に立つのは、処理を何段も重ねるときです。パイプを使わずに書くと、関数を入れ子にする必要があります。

```r
select(filter(stores, location == "駅前"), store_name, sales)
```

これでは内側から外側へ読まなければならず、どこで何をしているのか分かりにくくなります。パイプを使うと、上から下へ処理の順番どおりに読めます。

```r
stores |>
  filter(location == "駅前") |>
  select(store_name, sales)
```

`|>` は「そして次に」と読むと分かりやすいでしょう。「stores を取り出し、そして次に駅前の店に絞り、そして次に2列を選ぶ」という具合です。書くときは、行の**末尾**に `|>` を置いてから改行します。行の先頭に置くと、R はそこで命令が終わったと判断してしまいます。

経営企画部の仕事でも、「売上の大きい店を並べて、客単価も見たい」という依頼はよくあります。パイプを使えば、その依頼を言葉の順番どおりにコードにできます。

## 上位・下位の行を取り出す slice_max と slice_min

「ある列の値が大きい順に n 行」を取り出すには `slice_max()` を使います。`arrange(desc(...))` で並べ替えてから先頭を取るのと同じことを、1つの関数で書けます。

```r
stores |>
  slice_max(floor_m2, n = 3)
```

結果は値の大きい順に並びます。`arrange()` と違い、何行取り出すかを `n =` で指定するのがポイントです。反対に、値が小さい順に取り出すには `slice_min()` を使います。同じ値の店舗が境目にあると、両方とも残すので n 行より多くなることがあります。

## 処理の順番が答えを決める

パイプでつなぐときは、**順番**がとても大切です。たとえば「前年より売上が落ちた店舗だけで、地域ごとの店舗数を数える」なら、先に `filter()` で店舗を絞り、その後で `group_by()` と `summarise()` で集計します。

集計してから絞ろうとすると、うまくいきません。`summarise()` の後の表には、集計した結果の列しか残らないからです。店舗ごとの `sales` や `sales_last` はもう存在しないので、エラーになります。エラーにならない場合でも、「店舗」ではなく「地域の集計値」で絞り込むことになり、別の問いに答えてしまいます。処理を書く前に、「何を、どの単位で、どの順に」を言葉で確かめましょう。

## 数えるだけなら count

立地ごとの店舗数のように「グループごとの行数」だけが欲しいときは、`count()` が便利です。

```r
stores |>
  count(region)
```

これは `group_by(region) |> summarise(n = n())` と同じ結果を返します。数えた結果は `n` という列に入ります。`count(region, sort = TRUE)` とすると、多い順に並べてくれます。

## まとめ

パイプ `|>` は左の結果を右の関数に渡し、処理を上から下へ読める形にします。`slice_max()` と `slice_min()` で上位・下位の行を取り出し、`count()` でグループごとの行数を数えます。そして、絞り込みと集計の順番が結果を左右することを覚えておきましょう。

## 卒論・実務での使いどころ

データの加工手順をパイプで1本にまとめておくと、上司や指導教員が上から順に読んで手順を確かめられ、毎月の集計もすぐに作り直せます。
