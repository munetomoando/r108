## 問い

ここからは、そらまめマーケットのネット通販の顧客を扱います。上司からの依頼は「年末に解約しそうな顧客を前もって見つけ、クーポンを送って引き留めたい。誰が解約しそうか、予測できないか」です。0か1かの結果を予測する**分類**のモデルを、第93ステップの tidymodels の流れで作ります。

## データ：churn

`churn` は顧客5,000人の表です。2025年9月30日までの注文から、最後の注文からの日数 `recency`、注文件数 `frequency`、購入金額 `monetary` を作り、年齢 `age`、流入経路 `channel`、会員ランク `rank` を加えています。`churned` は、2025年10〜12月に注文が1件もなかった（解約した）なら yes、注文があれば no です。解約率は約25.7%です。

分類では、予測したい列を**因子**（第21ステップ）にしておきます。setup では `levels = c(1, 0)` で yes を最初の水準にしました。tidymodels の評価の関数は、**最初の水準を「注目する結果」**（ここでは解約）として扱うからです。

## ロジスティック回帰で学習する

第48ステップのロジットモデル（`glm(family = binomial)`）を、tidymodels では `logistic_reg()` と書きます。線形回帰の `linear_reg()` と入れ替えるだけで、分け方・レシピ・ワークフロー・学習の流れは第93ステップと同じです。

```r
set.seed(108)
churn_split <- initial_split(churn, prop = 0.75, strata = churned)
churn_train <- training(churn_split)
churn_test <- testing(churn_split)
```

`strata = churned` は、解約の割合が訓練データとテストデータでそろうように分ける指定です（層化）。解約のように一方が少ない結果では、無作為に分けると割合が偏ることがあるので、付けておくのが安全です。訓練は3,749人、テストは1,251人になります。顧客は互いに独立なので、時系列（第78ステップ）と違い、無作為に分けてかまいません。

表示される係数について1つ注意があります。中で動く `glm()` は、因子の**2番目**の水準（no＝継続）を1とみなします。そのため係数は「継続しやすさ」の向きで、解約の向きとは符号が逆です。係数を解釈したいときは、第48ステップのように `glm()` を直接使います。このステップの目的は予測なので、係数よりも予測の当たり具合を見ます。

## 予測確率と分類

第93ステップの `augment()` は、分類のモデルでは予測値 `.pred` の代わりに、次の3つの列を付けて返します。

```r
churn_pred <- augment(logit_fit, new_data = churn_test)
```

`.pred_yes` は解約する確率、`.pred_no` は継続する確率（合計1）、`.pred_class` は確率が0.5以上の側を選んだ分類です。確率の高い順に並べれば、そのまま「解約しそうな顧客のリスト」になります。最後の注文から長い日数がたち、注文が少ないブロンズ会員が上位に並ぶことを確かめましょう。

## 混同行列と正解率

予測と実際を突き合わせた2×2の表を**混同行列**といいます。

```r
conf_mat(churn_pred, truth = churned, estimate = .pred_class)
accuracy(churn_pred, truth = churned, estimate = .pred_class)
```

行が予測、列が実際です。対角線（yes を yes、no を no と予測）が当たり、それ以外が外れです。**正解率**（accuracy）は当たりの割合で、約0.780です。

ただし、この数字だけで喜んではいけません。テストデータの74%は解約しない人なので、全員を「継続」と予測しても正解率は約74%になります。混同行列を見ると、解約した321人のうち、当てられたのは80人だけです。一方の結果が少ないデータでは、正解率は役に立つかどうかを表しません。何を見逃しているかは、次のステップで指標を選んで測ります。

なお、このモデルは「誰が解約しそうか」を当てるもので、「recency を短くすれば解約が減る」という因果を示すものではありません（第91ステップ）。

## 卒論・実務での使いどころ

0か1かを予測するときは、テストデータでの混同行列を必ず示し、「全員を多い側と予測した場合」の正解率と比べて、モデルの価値を説明します。
