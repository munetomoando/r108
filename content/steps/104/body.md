## 問い

営業部長から「先週もらった図と、今日アプリで見た図で、関東の数字が違う。どちらが正しいの？」と聞かれました。先週から app.R を何度も直しましたが、どこをいつ変えたかは覚えていません。`app_最新.R`、`app_最新2.R` とファイルを増やすやり方では、すぐに分からなくなります。このステップでは、ファイルの変更の履歴を記録する道具 **Git** を使い、第102ステップのアプリ `sora_app` の履歴を残します。

## Git の考え方

Git では、フォルダの中のファイルの状態を、説明の文を付けて記録します。1回の記録を**コミット**、記録を持つフォルダを**リポジトリ**といいます。記録はフォルダの中の隠しフォルダ `.git` に入り、いつでも前のコミットと比べたり、戻したりできます。

| 操作 | コマンド | すること |
| --- | --- | --- |
| リポジトリを作る | `git init` | いまのフォルダで記録を始める |
| 状態を見る | `git status` | 変わったファイル、まだ記録していないファイルを表示 |
| 差分を見る | `git diff` | 前のコミットから何が変わったかを行ごとに表示 |
| 記録に入れる | `git add ファイル名` | 次のコミットに入れるファイルを選ぶ |
| 記録する | `git commit -m "説明"` | 選んだファイルの状態を記録する |
| 履歴を見る | `git log --oneline` | コミットの一覧を新しい順に表示 |

## Git を入れて、名前を設定する

1. **Git を入れる。**
   - Windows：https://gitforwindows.org/ から Git for Windows をダウンロードして実行します。設定は既定のままで構いません。
   - macOS：ターミナル（「アプリケーション」→「ユーティリティ」）で `xcode-select --install` を実行し、開発ツール（Command Line Tools）を入れます。Git はこれに含まれています。
2. **RStudio を再起動し、ターミナルを開く。** RStudio の左下の「Terminal」タブ（なければ「Tools」→「Terminal」→「New Terminal」）で `git --version` と入力し、版が表示されれば入っています。Windows では「Tools」→「Global Options...」→「Terminal」で「New terminals open with」を「Git Bash」にしておくと、本文のコマンドがそのまま使えます。Positron では「Terminal」パネルを使います。
3. **名前とメールアドレスを設定する。** コミットには、誰が記録したかが付きます。ターミナルで次の3行を実行します（名前とメールは自分のもの。第105ステップで GitHub に使うメールにそろえます）。最後の行は、最初のブランチ（記録の流れ）の名前を `main` にする設定です。

```sh
git config --global user.name "Sorano Hanako"
git config --global user.email "hanako@example.com"
git config --global init.defaultBranch main
```

## 何を記録しないか（.gitignore）

リポジトリは、第105ステップで GitHub に送り、人と共有します。最初から**記録してはいけないもの**を決めておきます。このステップでは、次の2つを「機密のファイル」とします。

- **社外秘のデータ（`data/` フォルダ）。** 店舗の売上は会社の外に出せない数字です。顧客の名前や住所のような個人情報を含むデータなら、なおさらです。卒論でも、個票データや聞き取りの記録は、利用の約束で配布が禁じられていることがあります。
- **API キーやパスワード（`.Renviron`）。** 第17ステップの e-Stat API の appId（アプリケーションID）のようなキーは、プロジェクトの `.Renviron` に `ESTAT_APPID=...` と書き、R では `Sys.getenv("ESTAT_APPID")` で読みます。スクリプトに直接書かず、`.Renviron` ごと記録から外します。

記録しないファイルは、プロジェクトの一番上の `.gitignore` というファイルに1行ずつ書きます。RStudio の作業用ファイル（`.Rproj.user/`）と、コンソールの入力の履歴（`.Rhistory`。キーを打ち込んだ行が残ることがあります）も外します。

```
.Rproj.user/
.Rhistory
.RData
.Ruserdata

# 社外秘のデータと API キーはリポジトリに入れない
data/
.Renviron
```

## 手順

1. **リポジトリを作る。** `sora_app` プロジェクトを開き、ターミナルで `git init` を実行します。RStudio のメニューで行うなら「Tools」→「Version Control」→「Project Setup...」で「Git」を選びます（RStudio が再起動し、右上に「Git」タブが出ます）。
2. **.gitignore を書く。** 「File」→「New File」→「Text File」で上の内容を書き、プロジェクトの一番上に `.gitignore` という名前で保存します（RStudio が作った `.gitignore` があれば、`data/` と `.Renviron` の2行を足します）。
3. **状態を見る。** `git status` を実行し、`data/` が一覧に**出ない**ことを確かめます。出るなら `.gitignore` の書き方か保存場所が違います。
4. **1つめのコミット。** `git add .gitignore app.R sora_app.Rproj` のあと、`git commit -m "地域を選ぶと売上の図が変わるアプリ"` を実行します。
5. **直して、差分を見る。** app.R の `geom_line() +` の次の行に `geom_point() +` を足して保存し、`git diff` を実行します。足した行が `+` 付きで表示されます（表示が長いときは `q` で抜けます）。確かめたら `git commit -am "月ごとの点を足す"` で記録します（`-a` は、記録済みのファイルの変更をまとめて add する指定です）。
6. **もう1つコミットする。** 例えば最初に選ばれている地域を `selected = "中部"` に変え、同じように diff を見てからコミットします。
7. **履歴を見る。** `git log --oneline` で、3つのコミットが新しい順に並ぶことを確かめます。

RStudio では、右上の「Git」タブで同じことができます。変わったファイルの「Staged」に印を付けるのが add、「Commit」ボタンで開く窓の下半分が diff、説明を書いて「Commit」を押すとコミット、「History」が log です。

## 間違えてコミットしたら

`.gitignore` を書く前に `data/` をコミットしてしまうと、後から `.gitignore` に書いても、過去のコミットにはデータが残ります。まだ GitHub に送っていなければ、`.git` フォルダを消して（隠しフォルダです。Windows はエクスプローラーの「表示」→「隠しファイル」、macOS は Finder で Command + Shift + .（ピリオド）で見えます）、手順1からやり直すのが確実です。アプリのファイルは消えません。

## 自分のPCで確認する

右の欄から `check_104.R` をダウンロードしてプロジェクトのフォルダに置き、コンソールで `source("check_104.R", encoding = "UTF-8")` を実行します。リポジトリ、コミットの数、`.gitignore` の中身、過去のコミットに機密のファイルが入っていないかを調べます。

## 卒論・実務での使いどころ

卒論のフォルダも最初に `git init` し、図や表の数字が変わる変更をするたびにコミットしておけば、「先週の数字」と「今日の数字」の違いを `git diff` で1行単位で説明できます。
